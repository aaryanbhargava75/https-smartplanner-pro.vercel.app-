1. High-Level Architecture Topology

Dayframe employs a Local-First, Edge-Assisted hybrid architecture. The UI executes entirely in the client browser for zero-latency interactions and 100% offline functionality, while compute-heavy AI tasks stream through low-latency edge functions.

LAYER 1: CLIENT PRESENTATION & OFFLINE ENGINE (PWA) CLIENT TIER

Single-Page Progressive Web App built with Vanilla HTML5/ES6, Dynamic SVG Circadian Dial Canvas renderer, and Web Speech API. Stores full state in browser localStorage with key isolation (smart-planner-user-{id}). Service Worker (sw.js) caches static assets for offline execution.

SVG Dial Renderer (60 FPS) Web Speech API Tesseract.js OCR Service Worker Cache UTF-8 BOM CSV Generator
▼ HTTPS / JSON Edge API (< 80ms) ▼
LAYER 2: EDGE GATEWAY & ROUTING CONTROLLER SERVERLESS TIER

Node.js Express / Vercel Serverless Edge Functions (server.js). Handles auth token verification, rate limiting, request schema validation, and secure API key management preventing secret leakage to clients.

POST /api/ai/brain-dump GET /api/auth/config POST /api/sync/supabase CORS / Security Headers
▼ Sub-Second Inference Stream (< 800ms) ▼
LAYER 3A: NEURAL AI INFERENCE AI ENGINE

Groq Cloud API running Llama-3.3-70b-versatile. Uses strict JSON Schema steering to extract entity arrays without hallucinating dates or currencies. Sub-second TTFT (<800ms) allows conversational responsiveness.

LAYER 3B: CLOUD MULTI-TENANT STORAGE DATA PERSISTENCE

Supabase PostgreSQL with strict Row-Level Security (RLS). Each user's tasks, journal entries, and finances are partitioned by authenticated Google UID. Fallback to Google Drive multipart diary backup.

2. Request-Response Data Pipeline (Multimodal Brain Dump)

[1. Capture] User speaks audio → Web Speech API records transcript → Base64 audio fallback payload created.
[2. Edge Dispatch] Client sends POST payload to /api/ai/brain-dump with prompt & context (current time, timezone).
[3. AI Parsing] Edge server proxies to Groq Llama-3.3-70b with system prompt enforcing JSON schema: { tasks[], schedule[], expenses[], incomes[] }.
[4. Client Hydration] Client merges JSON response into in-memory appData object, assigns collision-free slots on circular dial.
[5. Dual Sync] State is instantly saved to local localStorage and asynchronously synced to Supabase PostgreSQL table via RLS.

3. Database Schema & Multi-Tenant Data Model

Entity / Table Key Attributes & Schema Types Relational Constraints & Security Scope
tasks id (UUID), title (text), category (text), priority (enum), duration (int), status (enum) Scoped to user_id. Indexed on (user_id, date, status) for fast query retrieval.
journal (Schedule) id (UUID), startTime (HH:MM), endTime (HH:MM), title (text), notes (text) Maps directly to 360° circular dial sectors. RLS policy: auth.uid() = user_id.
expenses & incomes id, date (date), item (text), category (text), amount (decimal), type (enum) Enforces numerical non-negative constraints. Client formats via dynamic currency symbol.

3

4

Action: User clicks "Start Focus" on active task. 25-minute Pomodoro begins. Not-To-Do rule ("No Twitter before 2 PM") is pinned to screen.

UX Metric: Focus completion rate > 70%.

5
Evening Log, Reflection & 1-Click Excel Archive Cognitive State: Accomplished

Action: User marks tasks complete, checks total money spent today (₹640), and downloads formatted Excel spreadsheet for weekly record.

UX Metric: Day-7 retention rate > 42%.

Top 3 Product Improvement Opportunities (Prioritized)

P1: 1-Tap Capture Review Drawer High ROI

Problem: Dumping 5+ messy items at once can sometimes misallocate a tag.

Solution: Show a 3-second floating review drawer: "Found 2 Tasks, 1 Meeting, ₹500 Expense. [Approve All] or [Tweak]."

Target Metric: Median time to organization < 30s.

P2: Dynamic Adaptive Rescheduling Retention

Problem: Life happens. When a meeting runs 45 mins late, the user's entire scheduled afternoon collapses.

Solution: "1-Tap Ripple Reschedule": Pushes lower-priority tasks to the next open slot or suggests moving them to tomorrow.

Target Metric: Recovery rate of missed tasks > 60%.

P3: Proactive Smart Assistant Expansion

Problem: The planner is currently reactive; it waits for user input.

Solution: Proactively surface recurring bills, warning: "You have 4 hours of meetings back-to-back. Want to block a 15-min break?"

Target Metric: User engagement with smart prompts > 40%.

8. Senior PM Validation Protocol (How to Defend This Teardown)

3 Practical Experiments to Validate with Real Users:
  1. User Problem Discovery: Interview 8 working professionals regarding their daily friction points across WhatsApp, Google Calendar, and Splitwise. Track how many use paper or abandon todo apps within 7 days.
  2. Messy Input Stress-Testing: Benchmark 20 deliberately chaotic inputs (mixed Hindi/English speech with background traffic noise, blurry receipt photos, conflicting 2 PM meetings) to record AI error recovery rates.
  3. A/B Test Adaptive Rescheduling: Run a cohort test: Cohort A manually rearranges delayed tasks; Cohort B receives a 1-tap "Auto-Rebalance Schedule" prompt. Measure D14 retention delta.
